# Blog Simplified Standard

> 2026-05-04 phase-2 update: from the 0503 reading-system migration onward, the default daily blog output is content-first and Markdown-like. Premium visual components are optional aids, not the production default.

## Default page structure

- Hero only contains title, subtitle, date, and 3-5 table-of-contents anchors.
- Body uses semantic reading elements: `h2`, `h3`, `p`, `ul`, `ol`, `blockquote`, `table`, and source lists.
- Do not create multi-layer card grids purely for visual richness.
- Each core module should contain concrete explanation, not slogan-only short lines.
- Evidence boundary must appear inside each module or in a final source/boundary section.
- Source ledger should be readable as a list/table, not a long link soup.

## Article quality priority

1. Facts are verifiable.
2. Judgment is specific and falsifiable.
3. Portfolio action has clear boundaries.
4. The article leaves a reusable method or checklist.
5. The page is easy to read on desktop and mobile.
6. The visual layer feels polished.

Visual polish always ranks after content clarity.

## Daily module contract

A daily post should normally keep this order:

1. **00 PM brief** — one-sentence conclusion, portfolio posture, biggest risk/opportunity, evidence cutoff.
2. **01 Stock / case study** — identity tag first: holding, watchlist, candidate, or case-study. Do not let candidates enter action tables.
3. **02 Practical lesson** — one reusable decision rule, with a plain-language explanation and failure boundary.
4. **03 Creator / local-system digest** — creator content changes questions, not action cards, unless verified facts are independently sourced.
5. **04 News / observation radar** — separate holdings, promotion queue, and general radar.
6. **05 Action map** — true holdings only; include add/hold/reduce triggers and what would prove the thesis wrong.
7. **Sources and boundary** — official facts, news layer, creator layer, local-system layer, and personal judgment must be separated.

## Frontend compatibility rules

- The default reading container is `.blog-reading-page main.blog-article.markdown-body`.
- Reading width should stay close to 760-860px on desktop.
- Mobile pages must not depend on horizontal card grids for core content.
- Tables must be readable or horizontally scrollable on 390px width.
- Old premium components may remain for legacy pages, but new posts should not need them to make the content understandable.

## When premium components are still allowed

Use heavier components only when they improve comprehension:

- Scenario matrix for genuinely multi-branch decisions.
- Compact dashboard when it prevents repeated prose.
- Comparison card when it makes multiple holdings easier to scan.

Do not use components to hide thin content.
